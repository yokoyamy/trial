■ PHP 8.4/8.5最新仕様およびソケット/ストリーム通信に関する徹底厳守事項
1. 【非推奨関数の完全排除】
   - stream_context_set_option() はPHP 8.3で非推奨となったため使用禁止。代わりに stream_context_create() の配列オプションでコンテキストを設定すること。
   - str_getcsv() 等のCSV・文字列処理関数を使用する場合は、将来的な動作変更による警告を防ぐため、エスケープ文字等のパラメータを省略せず、必ず明示的に引数（例: str_getcsv($line, ",", "\"", "\\")）を指定すること。

2. 【stream_socket_enable_crypto() の厳格な引数指定】
   - stream_socket_enable_crypto() の第4引数 ($session_stream) に context（コンテキストリソース）を絶対に渡さないこと（TypeError: Argument #4 must be an open stream resource の発生防止）。
   - 暗号化通信を確立する際は、必ず正しい引数構成（第1引数: $stream, 第2引数: bool $enable, 第3引数: int $crypto_type）の3引数形式で呼び出すこと。
     例： @stream_socket_enable_crypto($fp, true, STREAM_CRYPTO_METHOD_TLSv1_2_CLIENT | STREAM_CRYPTO_METHOD_TLSv1_3_CLIENT)

3. 【HTTP response パースとChunked解凍の堅牢化】
   - fsockopen/stream_socket_client 等で受信したレスポンスのヘッダーとボディの分離には、\r\n\r\n および \n\n の両方の改行コードに対応すること。
   - Transfer-Encoding: chunked の場合は、デコード処理（サイズヘッダーの除外）を確実に行い、余計なヘッダーや空行が混入した状態で json_decode() が実行されてパースエラーになる現象を完全に防止すること。
4. 【JSONパースエラー（Syntax error）の完全防止とHTTPレスポンス検証】
   - cybozu.com から受信したレスポンスに対して json_decode() を実行する前に、必ず HTTP ステータスコード（例: HTTP/1.1 200 OK）を確認すること。
   - ステータスコードが 200 以外の場合は、レスポンスボディ（またはHTML/エラー文言）を直接例外メッセージ（Exception）としてスローし、HTML文言を json_decode() に渡して Syntax error が発生するのを防ぐこと。
   - Chunked解凍（decodeChunked）処理後は、trim() を通して先頭・末尾の不要な改行や空白を除去してから json_decode() を実行すること。

【追加指示：TLS/SSLハンドシェイクエラーの完全回避（プロキシソケット通信用）】

プロキシ経由の CONNECT ソケット通信において「TLSハンドシェイクに失敗しました」が発生しないよう、以下のロジック・設定を厳格に実装してください。

1. ソケット生成時の SSL コンテキスト適用と SNI 設定:
   `stream_socket_client`（または `fsockopen`）でプロキシに接続する際、必ず以下のオプションを設定したコンテキストを作成・適用してください。
   $context = stream_context_create([
       'ssl' => [
           'verify_peer'       => false,
           'verify_peer_name'  => false,
           'allow_self_signed' => true,
           'peer_name'         => $targetHost, // SNI用に接続先ドメイン（例: xxx.cybozu.com）を明示指定
           'SNI_enabled'        => true,
       ]
   ]);
   ※ stream_socket_client を使用し、第6引数に上記 $context を渡してソケットを開いてください。

2. HTTP CONNECT 成功後の TLS ハンドシェイク手順:
   ① プロキシサーバー（$proxyHost:$proxyPort）へ接続。
   ② `CONNECT {targetHost}:443 HTTP/1.1\r\nHost: {targetHost}:443\r\n\r\n` を送信。
   ③ レスポンスの1行目が `HTTP/1.1 200`（Connection Established）であることを確認。
   ④ 200を確認した直後に `stream_socket_enable_crypto()` を実行して暗号化を有効化する。
      @stream_socket_enable_crypto($socket, true, STREAM_CRYPTO_METHOD_TLSv1_2_CLIENT | STREAM_CRYPTO_METHOD_TLSv1_3_CLIENT);

3. エラーメッセージの明確化:
   `stream_socket_enable_crypto()` の戻り値が `false`（ハンドシェイク失敗）となった場合、処理を中断し、「TLSハンドシェイクに失敗しました。接続先: {targetHost}, プロキシ: {proxyHost}:{proxyPort}」という詳細な例外（Exception）をスローしてください。

修正後も制約事項通り、index.php 1ファイル丸ごと差し替え可能な形で出力してください。

## 2. 実装およびコード設計の再発防止策

今後同様のエラーを発生させないため、以下の設計・実装ルールを徹底してください。

■ 対応指示
以下の要件を満たすよう、`index.php` の処理ロジックおよび状態保持構造を見直してください。

1. **状態（セッション / POSTデータ）の保持**
   - 組織を選択して画面のリロードまたはフォーム送信（あるいはAjax通信）が発生する場合でも、既存のユーザー情報（セッションデータやPOSTされた入力値）が保持されるよう修正してください。
   - 組織変更イベントによってクリアすべき項目と、維持すべき項目を明確に分離してください。

2. **PHP・JavaScriptにおけるイベント処理とレンダリングの最適化**
   - JavaScriptでのDOM書き換え時に、予期せぬ範囲の要素（ユーザー情報エリアなど）をリセットしないように実装してください。
   - PHP側のリクエスト判定（POST/GET）を厳密に行い、組織選択時のパラメータ送信であっても、ユーザー情報の保持ロジックをスキップしない構造にしてください。

3. **単一ファイル（index.php）内での関数・変数のカプセル化**
   - 他処理や既存ロジックとの競合を防ぐため、名前空間（Namespace）の使用や無名関数・クラスによるカプセル化を行い、変数の意図しない上書き（汚染）を防いでください。

4. **制約事項の遵守**
   - 修正にあたっては、既存の制約事項（index.php 1ファイルで完結、PHP 8.5対応、エスケープ処理の徹底、2バイト文字の文字化け対策など）を崩さずに全コードを差し替え可能な形式で提示してください。

原因特定箇所と修正内容の解説を添えて、修正後の index.php の完全なコードを提示してください。

# 実装要件

## 1. 実行環境・構成
- Apache 2.4＋PHP 8.4/8.5、データベースなし。
- `index.php` 1ファイルにPHP・HTML・CSS・JavaScriptを格納する。
- cURLは使用しない。
- データはアプリルート配下のJSONファイルへ保存する。
- 文字コードはUTF-8に統一する。
- 将来DBへ移行できるよう、各データはIDで関連付ける。

## 2. データファイル
アプリルート配下に以下のJSONファイルを使用する。

- `data/settings.json`：SMTP・kintone等の設定
- `data/surveys.json`：アンケート基本情報
- `data/groups.json`：アンケートのグループ
- `data/questions.json`：質問
- `data/options.json`：選択肢・分岐
- `data/customers.json`：kintoneから取得した顧客
- `data/recipients.json`：アンケートごとの送信対象
- `data/mail_logs.json`：メール送信履歴
- `data/responses.json`：回答
- `data/response_answers.json`：質問ごとの回答内容

各ファイルはJSON配列として保存する。

各レコードには一意なIDを持たせ、関連データはIDで参照する。
質問番号・顧客名・メールアドレス・表示文言を関連付けのキーに使用しない。

JSONファイルが存在しない場合は、空の配列または初期設定として扱う。
JSONの読み込み・保存に失敗した場合は処理を成功扱いにしない。
保存時は同時更新によるデータ破損を防止する。

## 3. アンケートデータ
アンケートには以下を保持する。

- ID
- 名称
- 説明
- 状態
- 公開開始日時
- 公開終了日時
- 作成日時
- 更新日時

状態は「下書き・公開中・終了」とする。

グループにはID・アンケートID・名称・表示順を保持する。

質問にはID・グループID・質問文・回答形式・必須／任意・表示順を保持する。

選択肢にはID・質問ID・文言・表示順・分岐先質問IDまたは終了指定を保持する。

## 4. 送信・回答データ
送信対象には以下を保持する。

- ID
- アンケートID
- 顧客ID
- 送信状態
- 送信日時
- 回答状態

メール履歴には以下を保持する。

- ID
- 送信対象ID
- 件名
- 本文
- 送信日時
- 成否
- エラー内容
- 再送元ID

回答には以下を保持する。

- ID
- アンケートID
- 送信対象ID
- 回答日時
- 完了状態

回答内容には回答ID・質問ID・回答値を保持する。

## 5. アンケート
- 作成、編集、保存、内容確認、公開、終了、下書き削除を行える。
- グループ・質問・選択肢の追加、削除、並べ替えを行える。
- 質問番号は表示用として自動生成する。
- 回答形式は自由記述・単一選択・複数選択とする。
- 単一選択の選択肢ごとに分岐を設定できる。
- 分岐先は質問IDで管理する。
- 存在しない分岐先や循環する分岐は保存できない。
- 公開中・終了後の不正な変更を防止する。
- 終了したアンケートは回答を受け付けない。

## 6. バリデーション
保存・公開・送信・回答の各処理でサーバー側でも検証する。

- 必須項目
- 文字数
- メールアドレス
- ポート番号
- 日付・期間
- 回答形式
- 選択肢
- IDの存在
- 分岐先
- 回答値と質問形式の一致
- アンケート状態

分岐で表示されなかった質問は必須未回答として扱わない。

## 7. メール
- 顧客検索・複数選択・送信前確認を行える。
- 公開中のアンケートのみ送信できる。
- 対象者ごとに送信結果を記録する。
- 失敗者のみ再送できる。
- 二重送信を防止する。
- 再送しても過去の履歴を上書きしない。
- SMTP設定未完了時は送信できない。

## 8. 回答・集計
- 顧客一覧に存在しない人も回答できる。
- 必須質問を未回答のまま送信できない。
- 分岐に従って表示する質問を決定する。
- 回答の二重登録を防止する。
- 回答数・回答率・未回答数は保存データから算出する。
- 分岐で表示されなかった質問は集計対象から除外する。
- 選択式は選択肢別の件数・割合を表示する。
- 自由記述は回答内容を表示する。

## 9. kintone API
- APIトークンは使用せず、ログイン名・パスワードで認証する。
- `stream_context_create` と `file_get_contents` を使用する。
- 入力されたプロキシ `host:port` を全kintone通信で利用可能にする。
- プロキシ使用時は `proxy` と `request_fulluri => true` を設定する。
- SSL証明書検証は行わない。
- GETは `http_build_query(..., PHP_QUERY_RFC3986)` でクエリを生成する。
- GETに `content` を設定しない。
- POST/PUTはJSON本文と `Content-Type: application/json` を使用する。
- URLは `https://` や `.cybozu.com` の二重付与を防止する共通処理を使用する。
- 接続テストを実装する。
- kintoneの `code`・`message`・`errors` を解析してエラー表示する。
- パスワード等の機密情報をログやレスポンスへ出力しない。

## 10. セキュリティ
- 状態変更処理はCSRFトークンで検証する。
- セッションは `cookie_httponly=true`、`cookie_samesite=Lax` とする。
- CSRF等のセッション値はアプリ固有のセッションキーに保存する。
- `X-Frame-Options: SAMEORIGIN` を設定する。
- `X-Content-Type-Options: nosniff` を設定する。
- PHPの動的HTML出力にはNULL安全な `h()` を使用する。
- JavaScriptのDOM描画は原則 `textContent` を使用する。
- パスワード・認証情報・トークンを画面・ログへ平文出力しない。

## 11. PHP 8.4/8.5・名前空間
- PHPファイル先頭でアプリ固有の階層型namespaceを宣言する。
- 汎用的な単一namespaceは禁止する。
- ヘルパー関数もnamespace内に定義する。
- `h()` は以下の仕様とする。

`function h(?string $str): string`

- `$http_response_header` を直接参照しない。
- レスポンスヘッダーは `http_get_last_response_headers()` を使用する。
- 曖昧な関数定義や独自フォールバックを追加しない。
- JSON APIレスポンスはバッファを破棄し、JSONのContent-Typeを設定して出力後、必ず `exit` する。

## 12. JavaScript
- すべての処理を `DOMContentLoaded` 内で実行する。
- イベント登録前に対象要素の存在を確認する。
- 存在しない要素があっても後続処理を停止させない。
- 非同期通信開始前に対象ボタンを即座に `disabled = true` にする。
- 同時にローディング表示を開始する。
- 通信終了時は成功・失敗にかかわらずボタンを復帰する。
- APIレスポンスの存在しないプロパティを直接参照しない。
- DOM描画は原則 `textContent` を使用する。
- `innerHTML` 使用時は必ずエスケープ済みデータのみを渡す。

## 13. 頻出エラー防止
以下を必須とする。

- `namespace` と関数・定数の参照先を一致させる。
- `h()` 等の関数を重複定義しない。
- JSONファイルの読み書き前にパスと権限を確認する。
- JSONデコード失敗を正常データとして扱わない。
- IDの存在確認なしに関連データを参照しない。
- GETのkintone APIへ `content` を設定しない。
- kintoneのプロキシ設定を通信ごとに付け忘れない。
- `https://` や `.cybozu.com` をURL生成時に二重付与しない。
- APIレスポンス後にHTMLを出力しない。
- `DOMContentLoaded` 外でDOMを操作しない。
- 存在しないDOM要素へイベントリスナーを登録しない。
- 非同期通信前のボタン無効化を忘れない。
- `finally` 相当の処理でローディング表示とボタン状態を必ず復元する。
- ユーザー入力やAPIレスポンスを未エスケープでHTMLへ出力しない。
- パスワード・認証情報をエラーメッセージへ含めない。

## 14. 処理単位
以下を個別の処理として実装する。

- アンケート取得・保存・公開・終了
- 顧客取得・検索
- メール送信・再送
- 回答送信
- 回答状況・結果取得
- SMTP設定・接続確認
- kintone設定・接続確認

各処理で、対象データの存在・現在状態・入力値を確認してから実行する。

## 15. 業務フロー
アンケート作成
→ 編集・分岐設定
→ 保存・内容確認
→ 公開
→ 顧客選択
→ メール送信
→ 回答受付
→ 回答状況確認
→ 回答結果確認
→ 必要に応じて再送
→ アンケート終了

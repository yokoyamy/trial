# 実装要件

## 1. 基本
- Apache＋PHPで動作する。
- データはJSONで保存する。
- 画面表示は保存データを基準とし、固定値で管理しない。
- 各データは一意なIDで関連付ける。
- 画面側だけでなくサーバー側でも入力値を検証する。

## 2. データ
以下を保存する。

- アンケート：ID、名称、説明、状態、公開期間、グループ、作成・更新日時
- グループ：ID、名称、表示順
- 質問：ID、グループID、質問文、回答形式、必須／任意、表示順
- 選択肢：ID、質問ID、文言、表示順、分岐先
- 顧客：ID、kintone識別情報、氏名、メールアドレス等
- 送信対象：アンケートID、顧客ID、送信状態、回答状態
- 送信履歴：送信対象、日時、件名、本文、成否、失敗理由
- 回答：ID、アンケートID、送信対象ID、回答日時、回答内容

質問・選択肢との関連付けには表示番号や文言ではなくIDを使用する。

## 3. アンケート
- グループ・質問の追加、削除、並べ替えを行える。
- 質問は同一グループ内で並べ替える。
- 質問番号は表示用として自動生成する。
- 単一選択の選択肢ごとに「次の質問」「指定質問」「終了」を設定できる。
- 存在しない分岐先や循環する分岐は保存できない。
- 状態は「下書き→公開中→終了」とする。
- 公開・終了後の不正な状態変更はできない。

## 4. バリデーション
保存・公開・回答・送信の各処理で以下を確認する。

- 必須項目が入力されている。
- 回答形式・状態などの値が正しい。
- 選択式質問に選択肢が存在する。
- 分岐先が存在する。
- 不正なIDを受け付けない。
- 公開期間の前後関係が正しい。
- 回答値が質問の形式・選択肢と一致する。
- 分岐で表示されなかった必須質問は未回答エラーにしない。

## 5. メール
- 顧客検索・複数選択・送信前確認を行える。
- 送信結果を対象者単位で記録する。
- 失敗者のみ再送できる。
- 通常送信による二重送信を防止する。
- 再送しても過去の送信履歴を上書きしない。

## 6. 回答・集計
- 自由記述、単一選択、複数選択に対応する。
- 回答送信を二重登録しない。
- 顧客一覧にない回答者も回答できる。
- 回答数・回答率・未回答数等は保存データから算出する。
- 分岐によって質問を表示しなかった回答者は、その質問の集計対象から除外する。
- 選択肢別の回答数・割合、自由記述を確認できる。

## 7. 外部設定
- SMTP設定とkintone設定を保存・変更できる。
- 接続確認と設定保存を区別する。
- SMTP・kintoneのパスワードは画面やログに平文表示しない。
- kintoneから取得した顧客と過去の送信・回答履歴との関連を維持する。

## 8. 処理・エラー
以下を個別の処理として扱う。

- アンケート保存・公開・終了
- 顧客取得
- メール送信・再送
- 回答送信
- 回答状況・結果取得
- SMTP／kintone設定・接続確認

存在しないデータ、状態に合わない操作、二重操作は受け付けない。
エラー時は成功扱いにせず、利用者が原因を確認できる内容を表示する。

## 9. DB移行
将来DBへ移行できるよう、以下の単位に分離できる構造とする。

`surveys / groups / questions / options / customers / recipients / mail_logs / responses / response_answers / settings`

質問番号・表示文言をキーにせず、各IDで関連付ける。
